# Маяк — SEO-аналитика

Сервис с личным кабинетом: несколько проектов, дашборды по органике и брендированные SEO-отчёты. Данные тянутся по API из Яндекс Метрики, Google Search Console и Яндекс Вебмастера; пока интеграции не подключены, дашборд работает на правдоподобных демо-данных.

## Запуск

```bash
npm install
npm run dev      # http://localhost:3000
```

Продакшен: `npm run build && npm start`. Перед продакшеном задайте `AUTH_SECRET` в окружении (подпись сессионных куки). Пошаговый деплой на VPS (Ubuntu + nginx + systemd + HTTPS) — в [DEPLOY.md](DEPLOY.md), готовые конфиги — в `deploy/`.

База — SQLite в `data/searchlight.db`, создаётся автоматически.

## Что на дашборде

- **Метрика**: визиты/посетители/просмотры/отказы, динамика трафика и органики, источники, разбивка органики на бренд/небренд (по брендовым словам проекта через фильтр поисковых фраз), страницы входа из поиска, поисковые системы, цели с конверсией (воронка).
- **GSC**: клики, показы, CTR, средняя позиция, динамика, топ запросов и страниц.
- **Вебмастер**: ИКС, страницы в поиске/исключённые, популярные запросы за 14 дней.
- **Позиции**: топ-3/топ-10, средняя позиция, видимость и динамика по дням — из Топвизора или Keys.so.
- **Сравнение периодов**: у всех KPI стрелки ▲▼ с % к предыдущему отрезку той же длины (рост отказов и средней позиции подсвечивается как ухудшение).
- **Отчёт** (`/p/<id>/report`): печатная версия с логотипом клиента — кнопка «Печать / PDF».
- **Публичная ссылка** (`/r/<token>`): тот же отчёт без входа в кабинет — для отправки клиенту. Только чтение, без настроек и токенов; токен генерируется/отзывается в настройках проекта.

## Подключение позиций (Топвизор / Keys.so)

В настройках проекта, блок «Позиции»:
- **Топвизор** — API-токен и User ID (Топвизор → Настройки → API), затем выбор проекта из списка (регион подставится сам). Даёт динамику топов по дням.
- **Keys.so** — API-токен; видимость и распределение по топам берутся по домену проекта.

Если заполнены оба — приоритет у Топвизора. Без подключения блок показывает демо-данные.

## Подключение интеграций — в один клик

В настройках проекта есть кнопки **«Войти через Яндекс»** и **«Войти через Google»**: пользователь подтверждает доступ в своём аккаунте, сервис сам получает и хранит токены, подбирает по домену счётчик Метрики, хост Вебмастера и ресурс GSC (их можно поменять в выпадающих списках). Токен Google обновляется автоматически по refresh token.

Чтобы кнопки работали, один раз настройте серверные ключи (скопируйте `.env.example` → `.env`):

**Яндекс** — [oauth.yandex.ru](https://oauth.yandex.ru) → «Создать приложение»:
- права: «Яндекс.Метрика — получение статистики», «Яндекс.Вебмастер — чтение»;
- Redirect URI: `http://localhost:3000/api/oauth/yandex/callback` (и адрес прод-домена);
- ClientID/secret → `YANDEX_CLIENT_ID`, `YANDEX_CLIENT_SECRET`.

**Google** — [console.cloud.google.com](https://console.cloud.google.com) → APIs & Services:
- включите **Search Console API**;
- OAuth consent screen (scope `webmasters.readonly`), затем Credentials → OAuth client ID (Web application);
- Authorized redirect URI: `http://localhost:3000/api/oauth/google/callback` (и прод-домен);
- ключи → `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`.

Если dev-сервер слушает другой порт, подставьте его в redirect URI.

**Запасной вариант (без OAuth-кнопок)** — в настройках проекта есть блок «Подключить вручную»: OAuth-токен Яндекса, для Google — JSON сервисного аккаунта (его e-mail добавьте в пользователи ресурса GSC) или готовый access token.
